## WHAT I ASKED AI TO DO

1.  Help design the SmartSched product and translate the Intelligent
    Timetable Generator problem into a practical web application with a
    clear workflow, data model, API, and UI.
2.  Assist with implementation of the React frontend and Django REST
    backend, including timetable generation, constraint validation, API
    integration, and UI components.
3.  Review the generated timetable and help identify implementation
    issues, improve candidate ordering, and prepare the project for
    submission.

A useful prompt was to define the Edumerge Intelligent Timetable
Generator requirements and ask for a production-style assessment

and weekly-session constraints while explaining impossible schedules.

The most useful part of the interaction was iterating on the actual
generated result instead of treating generated code as automatically
correct.

## AI OUTPUT THAT WAS WRONG / NEEDED IMPROVEMENT

The initial timetable candidate selection logic was valid from a
hard-constraint perspective but tended to select the earliest available
periods repeatedly. This produced a timetable that was technically
schedulable but unnecessarily concentrated in early periods.

There was also an integration issue during development where the
frontend could not reach the Django API while the backend server was not
running. This was identified during actual application testing rather
than assumed from the code.

## HOW I IDENTIFIED THE PROBLEM

I ran the application and inspected the generated timetable through the
Schedule page instead of assuming that successful code execution meant
the product behavior was correct.

I also checked the browser/API behavior when the frontend reported that
it could not connect to the backend.

## HOW I FIXED IT

For the timetable distribution issue, the candidate-selection logic was
improved so that available candidates are ordered using current
period/day usage and other scheduling signals while retaining the hard
constraints.

For the frontend/API issue, the Django server was started correctly and
the frontend API configuration was verified against the local Django
endpoint.

After the changes, the dashboard, timetable generation, schedule view,
division filters, and constraint pages were manually checked.

## VALIDATION PRINCIPLE

AI-generated code was treated as a starting point rather than as
automatically correct. The implementation was validated by running the
application, generating timetables, inspecting the resulting schedule,
checking API responses, and reviewing the constraint behavior.
